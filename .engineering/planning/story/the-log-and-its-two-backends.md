# EL-001 — The log and its two backends

## Intent

The append surface, the read surface, and the two backends that implement them, with the one
exercise that defines what they must agree on. No aggregates, no projections, no module changes.

## Acceptance

- `eventlog-core` declares the envelope, `StreamId`, `Expected`, the error taxonomy, and the store
  port. `StreamId` has no constructor without a tenant.
- `eventlog-sqlite` and `eventlog-postgres` implement it with the DDL in RFC 0020, generated by the
  kit and identical per module apart from the table prefix.
- `append` takes `Expected::{Any, NoStream, Exact}`; a version conflict returns the actual version
  rather than a bare error.
- Idempotency is enforced in the append transaction: a repeated `(tenant, stream, key)` returns the
  first attempt's version range; the same key with a different request hash is **refused**.
- Readers stop at the commit watermark. A test commits two overlapping transactions out of order
  and proves a reader at the cursor never skips the older one — the failure this exists to prevent
  is invisible without it.
- `eventlog-conformance` runs one body of assertions against SQLite file, SQLite `:memory:` and
  PostgreSQL. It follows `model/modules/modules/corpus/crates/corpus-store/src/contract.rs`, which
  is the only shared exercise in the repository and the reason M-022 was found.
- The component has its own workspace, gate, `CHANGELOG.md` and `AGENTS.md`, and releases under
  `eventlog-v*` tags.
