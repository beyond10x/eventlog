## Outcome

`JournaledRowChange` and `DurableJournalEntry`, the two capture journal types still hand-written in
`crates/eventlog-sqlite/src/durable_capture.rs`, are generated by `ess generate types --target rust`
like the other capture types, with no change to what a durable capture returns.

## Why

story:generate-capture-types-from-ess generated seven of the nine capture types on ess 0.59.0. The
journal row's `before` and `after` are `Optional<Json>` in `ess/capture/domains/capture.yaml`, and
the Rust target emits `EssPresence<serde_json::Value>`. With the generated crate's `exact-numbers`
feature off, which keeps `serde_json/arbitrary_precision` out of every crate that hashes request
bodies, a float re-parsed through `serde_json::Value` is not the value its stored text holds
(1.0715660391465826e-75 reads back as ...825e-75, then ...823e-75). The hand-written codec embeds
the row's stored text as `RawValue`. With the generated types, the adversary case
`the_durable_delta_is_the_in_process_delta_for_a_float_the_store_rewrites` fails.

## Waiting on

An ESS Rust target option that maps a `Json` value to its raw JSON text
(`Box<serde_json::value::RawValue>`), independent of `exact-numbers`:
https://github.com/beyond10x/ess/issues/577. Requested of ESS on
2026-10-14 with the reproducer above.

## Acceptance

- Both types are generated and used by eventlog-sqlite; `AWAITING_RAW_JSON` in
  `crates/eventlog-sqlite/tests/generated_capture_types.rs` is gone and the test holds no exception.
- `durable_capture_adversary.rs` passes unchanged.
- `serde_json/arbitrary_precision` stays absent from `cargo tree -e features` for every crate.
- The journal's stored format is unchanged: entries written before the change read the same.
